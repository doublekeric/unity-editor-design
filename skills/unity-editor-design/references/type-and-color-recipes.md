# 字体与色彩：在复杂内容上选择，而不是凭感觉换色

本参考用于字体、字号、字重、背景层次需要明显改善的任务。它提供选择方法和可修改起点，不是强制每个工具同一种皮肤。

## 先做真实内容校准

拿目标界面真实的标题、中文字段、英文文件名、路径、数值，放在最终字体和目标缩放下比较。至少包含一条很长的名称、一个警告、一组选中行、可用与禁用按钮。用高密度内容测试，不拿只有三行的空界面判断配色品质。

### 字体体系

- 独立数据工具常见起点：页面标题18–20px、组标题13px中等强调、正文/字段13px、辅助12px、真正次要元信息11px。正文14px只有在字库字面偏小或窗口较宽时再试，不用“越大越好”。
- 限制为两种主要字重：Regular用于绝大多数正文，Medium/Semibold只用于标题、当前对象、必要分节。中文字体没有真实Medium/Semibold时不要用合成粗体铺满界面；常规字重加适度字号通常更稳。
- 对齐不仅是控件边界，也看字面和基线。数值/单位同列右对齐；路径颜色弱于文件名但仍应可读；错误信息不能降到脚注等级。
- 一套中西文协调的UI字体通常优于“英文字体+未知中文回退”。字体选择需核对当前Unity TextCore/FontAsset能力，本机系统有字体不代表动态Font能直接显示。
- 不未经许可打包系统字体。已有获授权字体资源优先；本机演示可以内存使用已安装字库，遇到兼容问题明确回退且保留对照。

## 背景先定明度，再选强调色

不要把所有灰色都染成蓝色，再给每层不同蓝。先确定两三个中性表面，按明度区分导航、内容、输入；强调色只占小面积。

一种语义分配：

- 主背景与次表面：差别轻，划分结构但不抢数据。
- 控件默认/hover/pressed或selected：同一颜色体系中的连续状态。
- 结构边线弱，交互边线略清楚；键盘focus单独清晰。
- 正文与辅助文字：靠对比区分，辅助不是不可读。
- 主按钮与hover：集中强调，禁用与普通次按钮明显不同。

这个分法借鉴 [Radix 色阶角色说明](https://www.radix-ui.com/colors/docs/palette-composition/understanding-the-scale)，不是直接复制其CSS或声称Unity具备其对比保证。

## 两个不同的起点

### 中性石墨：长时间高密度工具

| 角色 | 参考色 |
|---|---|
| 导航 / 主内容 / 浮起控件 | `#1B1D1F` / `#222528` / `#2C3034` |
| hover / 边线 | `#34393E` / `#41474D` |
| 正文 / 辅助 / 禁用 | `#E8EAED` / `#B2B8C0` / `#737B85` |
| 选择底 / 选择文字 | `#263F3C` / `#B9E7DB` |
| 主操作 / 主操作文字 | `#94D5C3` / `#16362D` |
| 警告 / 警告底 | `#EDC681` / `#433725` |

背景尽量中性，微绿只用于选择和主操作。不要把每个状态都做彩色药丸，也不要求颜色一定是绿。

### 纸白：重文字、对照与设置

| 角色 | 参考色 |
|---|---|
| 导航 / 主内容 / 表头 | `#F0F0EE` / `#FCFCFA` / `#F3F3F0` |
| 控件 / hover / 边线 | `#FFFFFF` / `#E9EEEA` / `#D9DDDA` |
| 正文 / 辅助 / 禁用 | `#27312C` / `#667169` / `#949D96` |
| 选择底 / 主操作 | `#E1EEE6` / `#326C50` |
| 主操作文字 / 警告文字 | `#FFFFFF` / `#8C5A13` |

不把浅色背景改成米色宣传页，不给全界面加阴影。纸白的可读性来自低噪声、清晰字色和边界，不是“发白的深色界面”。

两套色板都是演示起点：应在真实状态里验证对比、选中与hover叠加、状态色辨认，不仅计算背景与正文一对颜色。

## 复杂度门槛

做技能示例或大改版时，不能只给一个干净的默认页：

- 至少有一屏代表性的密集数据、长名称与数字列。示例数据达到复杂度后再定行高；文本够清楚时可以减行距，不应先缩小字号。选中名不必加粗，底色/边线已足够时避免多重强调。
- 至少一个多选/混合状态、一个错误/冲突、一个空状态。
- 详情与表格同时存在时检查主次；窄窗可折叠次要详情，不一律挤压名称列。状态说明、主操作和对象不能跨很远才对应；排错/审查工具的详情先放问题与处理方式，再放类型占位和次要规格。
- 不把所有异常都上同一黄字：可自动处理、需人工确认、阻止执行应从真实行为区分，颜色和文字相互支持。
- 字体选择与色板使用同一组数据对比，避免把内容更少或布局更简单误认为风格更好。

审查时分别回答：文字是否协调？背景是否脏/压抑/刺眼？主要内容有没有被控件与彩色块淹没？小面积强调是否足够？然后才决定保留哪套风格。
