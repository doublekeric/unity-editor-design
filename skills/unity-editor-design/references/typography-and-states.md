# 字体与控件状态：按实际渲染校准

## 文字不是一组字号

新会话不应假设示例使用的字库、缩放或语言环境与目标相同。先检查目标窗口的默认字体/样式、Unity 版本、`EditorGUIUtility.pixelsPerPoint`；能查到时记录实际字体和中文回退，查不到就标注未知。

选择包含实际内容的校准样本，不在生产界面添加测试文案：

- 中文：构建记录、预览已就绪、设置与导入。
- 英文与数字：BuildProfile、release/1.8.0、09:42、02:18、1.25 MB。
- 路径：Assets/Editor/Build/ReleaseBuildProfileResolver.cs。

在正文、标题、输入框、表头中看同样内容：字面大小是否协调？基线是否一致？行框是否压住中文上下边？说明是否过灰？数值是否能纵向比较？只有看过渲染才定最终字号/行高。

### 字体选择

- 先沿用项目字体；继承系统字体通常比引入一套品牌字体合适，但继承不意味着不检查中文回退。
- 中文字形偏粗/偏细时，先核实字体和字重，再改字号。不要通过每处 +1px 补偿未知回退。
- 只有实渲验证后才采用系统字体，不能把 Windows 字体名写成跨平台保证。`Font.CreateDynamicFontFromOSFont` 返回对象不代表 UI Toolkit/TextCore 一定能正常显示；若文字消失或缺字，回退原字体并查该版本 FontAsset 支持，不继续盲调字号。临时字体要管理生命周期，不改全局 Editor 皮肤。
- Unity 2022.3.62f2 本机已验证可用的替代路径：`UnityEngine.TextCore.Text.FontAsset.CreateFontAsset("Microsoft YaHei UI", "Regular", 64)`，再用 `FontDefinition.FromSDFFont(fontAsset)`。这是TextCore资产，不是TMP_FontAsset；运行前先确认系统有该字体，别复制系统字体文件。完整内存helper见 `examples/complex/ReviewFont.cs`（相对skill根目录），只在需要字体替换时读，不作为跨平台默认。
- 标题的“重”不只来自 Bold。中文标题若显得板结，优先试正常字重加一级字号；英文表头和中文标签不能分别随意一套尺度。
- 给字号角色取名并集中定义，例如 Title / Body / Caption；同一角色默认用同一字体、字重、颜色。Inspector 与独立工具可用不同尺度。
- 小号文字只承载次要内容。错误原因、状态和操作对象不能为“精致”降为难读的脚注。

## 自定义控件保留行为，重新核对全部视觉层

Button、TextField、Toggle 的默认皮肤可能包含背景图、切片、边框和状态选择器。只覆盖 `backgroundColor` 不保证最终像预期。

改外观前看 `resolvedStyle`（尤其 backgroundImage、backgroundColor、border、padding、height）和元素实际 `worldBound`。先确认是哪层在画，不先猜默认皮肤就是原因。

### 页签检查

页签通常至少有这些组合：未选中、选中、未选中+hover、选中+hover、按下、键盘focus、选中+focus、禁用。

- 未选中默认背景应与条带融为一体；hover可以轻微变化，但不能看起来像第二个已选中项。
- 当前页指示与键盘焦点是两个含义，不用一根线混为同一状态。
- 底部分隔线要连续。子控件背景、margin或border不能盖住父容器底线的一段。
- 用 `resolvedStyle.height` 设置子控件高度时，注意父border/padding也占空间；有底线时使用实际内容高度，或把底线单独放在子控件绘制之外。
- 给 Button 添加下划线、图标等子节点后，重新测量宽度。部分UI Toolkit布局不再按 `button.text` 自动撑开；绝对定位子节点也不提供固有宽度。使用独立Label内容、合理minWidth或测量后的宽度，不让文字超出26px之类的实际按钮框。
- 不强行移除原生类名来解决未知问题。确需完全自定义外观时，仍保留原生Button事件/键盘机制，并明确补齐hover、pressed、focus、disabled。

### 验证最小闭环

1. 截下异常状态，记录能复现的选择/hover/尺寸。
2. 用实际样式/边界形成能失败的断言，例如“未选中按钮下边界不能覆盖条带分隔线”。
3. 修一个原因，重看同状态；不是顺便改颜色后觉得好一点。
4. 两个页签互换选择后再检查；正常/最小尺寸、深浅配色都看。
5. 人工注入事件或直接设置焦点只能证明程序化状态，不能宣称真实鼠标/键盘已验收。

## 布局检查针对任务，不针对本例

- 独立窗口如果全局标题、页签、页标题、说明连占半屏，减少重复标题或把次要元信息移到旁边；不是每个新工具都加三层顶部。
- 说明跟随它解释的输入/预览；不要把关键约束丢在远离内容的底角。
- 窄 Inspector 保留字段密度与序列化编辑习惯，不套工作台侧栏、大标题或品牌栏。
- 样例只有少量数据时仍要显示典型长文本、失败态和空态，否则漂亮默认图不能证明可用。
