# 编辑器工具的视觉方向

## 常见失败不是“不够花”

- 标题、正文、辅助文案几乎同一字号和重量，视线没有先后顺序。
- 工具条、页签、表头、底栏切成很多相似横带，靠线分组而不是靠比例。
- 按钮像零散的小标签，主要操作看起来接近禁用态。
- 大片留白与细密数据并存，密度没有统一逻辑。
- “沿用原生、克制、少装饰”成为不做设计的借口。

修复不是加渐变、品牌字体或更多功能，而是把视觉决定做完整。参考 [复杂示例](../examples/complex/README.md) 时理解信息关系，不复制外壳。

## 参考的用途

### Unity Foundations：可读性与使用习惯

- [Typography](https://www.foundations.unity.com/fundamentals/typography)：密集界面的基础字号与少量标题级差；Project Settings 一类标题可有更大的尺度，不是所有文字都必须一样小。
- [Content Organization](https://www.foundations.unity.com/patterns/content-organization)：距离区分组，容器服务共同操作，背景层次表达层级。Inspector 的紧凑字段/组间距不能套成独立窗口的全部规格。
- [Toolbar](https://www.foundations.unity.com/components/toolbar)：按作用范围和操作类型分组，同类工具条保持一致，不为填满空间放控件。

这些是约束参考，不要求某个工具必须长成默认 Inspector。

### 成熟桌面应用：结构与表面

[Linear UI redesign](https://linear.app/now/how-we-redesigned-the-linear-ui) 可参考应用导航与页面内容分层、顶部与侧栏统一、跨列表/分栏/主题检查一致性。不是借营销网页的 Hero，也不是复制品牌。

文章原则不能替代图片依据。优先实际查看用户或项目给出的图；外部图片拿不到则注明限制并继续，不反复等待。

### 开源设计 skill：判断过程

Anthropic 与 MengTo 提供“依据真实内容设计、避免无意义默认样式”的判断方法，见 [sources.md](sources.md)。它们不是 Unity 组件库，仓库人气不能代替结果检查。

## 把原则变成可执行方案

| 维度 | 独立数据工具的一种起点 |
|---|---|
| 标题 / 正文 / 辅助 | 约 17–19 / 13 / 12；11 只用于次要标签 |
| 间距 | 8 小间隔、12–16 组内布局、20–24 内容边距；一组不混多条起线 |
| 行密度 | 普通资源约 28–36；对照预览约 36–40；按真实内容修正 |
| 按钮 | 约 28–32 高；启用/禁用清楚，主次操作及各状态成套设计 |
| 颜色 | 少量背景层次，清楚的文字对比，小面积强调 |
| 边界 | 先用背景和间隔，分隔线留给主要分区或必要表头 |

这不是每个 Inspector 都应采用的数值；有明确项目风格或字库表现不同时，按参考和截图调整。

## 关键取舍

**两列与两行没有绝对答案。** 原名/目标名需要直接比较时，宽窗先试左右对照；窄窗两列都截断时，转为双行、详情或可调列宽。不要把一个例子的选择写成通用规则。

**数据少，不等于需要统计卡填空。** 四条预览不需要一整栏巨大数字。数量和就绪状态放在预览标题/操作区通常更有效。

**原生行为与默认皮肤分开。** Button、TextField 可保留键盘和编辑能力同时改外观；ListView 保留虚拟化和选择。不要用 Label 假装控件，也不必接受所有默认灰框。

**留白是结果，不是指标。** 表格可自然留空；但不应把路径、计数、动作拆成三层底栏，再把间隙称为克制。

## 独立审美 review

给 reviewer 真实截图，不先给测试数字或“已优化”的结论：

> 只按桌面工具设计质量判断。第一眼的重点是什么？文字、比例、间距、表面和组件细节有哪些具体弱点？列三项最值得改的问题。可以判审美不通过，不用编译成功、无遮挡或可读替代审美判断。

修改后同尺寸对照。Reviewer 是独立意见，不代替用户认可。
