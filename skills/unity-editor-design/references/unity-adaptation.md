# 网页审美原则怎样迁到 Unity 编辑器

适用基线：Unity 2022.3 LTS。其他版本先核实 API，不用 Unity 6 的能力反推 2022.3。

## 保留原则，替换实现

| 网页经验 | 编辑器中的用法 | 不照搬的部分 |
|---|---|---|
| 统一的间距和文字层级 | 列表行、工具条、字段标签和分节保持一致 | 大号品牌字体和宣传页标题 |
| 先分组后画容器 | 文件树、表格、详情之间用分隔线和间距组织 | 每个区域都包一张圆角卡片 |
| 单一主要任务 | 主要操作稳定，作用对象和预览范围可见 | 每个区域放一颗彩色 CTA |
| 色彩语义一致 | 中性背景、选中与焦点清楚、警告有文字 | 禁用某种颜色、禁纯黑等绝对规则 |
| 窗口自适应 | 最小宽度、可调分栏、长路径处理、表格滚动 | 手机断点、`vw`、`clamp()`、CSS Grid |
| 动效解释变化 | 选择和校验反馈直接，必要时简短过渡 | 无限微动效、列表交错入场、悬浮弹簧 |

## 一组起点，不是 Unity 官方规格

先继承相邻工具的尺寸。如果没有可参考实现，可以用这些**逻辑像素**开始，再按中文字体、缩放和截图修正：

| 项目 | 紧凑工具起点 |
|---|---|
| 基础间距 | 4 / 8 / 12 / 16 |
| 普通列表行 | 紧凑 Inspector 约 24–28；独立资源窗口约 32–36；按内容决定 |
| 主工具条 | 28–32；展示标题的页面头可独立分配高度 |
| 内容区内边距 | 紧凑 Inspector 约 8–12；独立窗口约 20–24 |
| 正文 / 字段 | 保留字体与中文回退；正文约 12–13，不为密度一味缩字 |
| 标题 | Inspector 通常靠字重和间距；独立窗口可用约 17–19 的明确级差 |
| 控件圆角 | 原生或统一定制；自定义控件约 4–6，不逐控件随意选择 |

不要把这些值当成像素级兼容保证。原生 Toolbar 默认行高未必与此相同，尽量让同一排控件使用同一种来源。字号还要考虑字体、中文、Editor UI Scaling 和 `EditorGUIUtility.pixelsPerPoint`。

## UI Toolkit / USS

- 默认沿用 EditorWindow 面板的原生控件与主题。对自定义区使用本工具的语义名，例如 `--tool-surface`、`--tool-border`、`--tool-text-muted`、`--tool-selection`。
- 可从目标版本确认存在的 `--unity-colors-*` 变量取值。不要猜一个变量名，不要假设所有运行时 UIDocument 和自建 TSS 都有同一组变量。
- 原生变量不够时，为深浅主题集中提供成对颜色或共享 StyleSheet。`EditorGUIUtility.isProSkin` 可用于选择调色板；显示模式改变后需重建或刷新自定义样式。不要靠重写编辑器全局首选项来展示两种颜色。
- USS 与 CSS 相似但不相同。布局基于 Yoga/Flexbox；检查属性支持表后再写。特别留意 CSS Grid、`gap`、伪元素、媒体查询、浏览器字体加载与 `calc()` 不能当作默认能力。
- 不要用行内 `style` 散落所有视觉值。少量独立 C# 演示可用集中调色板来减少安装负担；正式工具优先复用已有 USS 和原生类。
- 非滚动内容区正确设置伸缩与最小尺寸；长路径可截短，但必须能通过 tooltip、复制或详情读到完整值。大列表使用虚拟化控件，不复制上百个静态 Label。
- 只有在支持的前提下才写动效。UI Toolkit 2022.3 支持部分 USS transition，但工具通常不需要；IMGUI 不套用 DOM / CSS 动画方案。

## 原生状态不是一张效果图

检查 hover、focus、selected、disabled 四种状态。选中表示对象，焦点表示键盘当前操作位置；它们可能同时出现。

使用 `ListView` 等原生控件保留选择、键盘和滚动能力。复杂 TreeView / MultiColumnListView 的创建和回收回调必须遵循目标版本；样式不能破坏交互。

颜色只辅助状态：例如“2 项路径冲突，不能执行”，而不是只给文件名涂红。没有结果时保留搜索输入和清除筛选入口，不显示一个孤立的空白面板。

批处理的预览数、勾选数、按钮影响数必须一致。修改搜索或选择后，旧预览不能继续假装有效。若预览不检查磁盘、重名或权限，界面明确标注为演示，而不是显示“检查通过”。

## IMGUI 的迁移规则

保留现有 `EditorGUILayout`、`EditorGUI`、`EditorStyles` 及窗口行为。用统一 labelWidth、行高、组间距、折叠区和状态提示改善层级；不为了视觉重写业务代码。

确需自定义 `GUIStyle` 时缓存实例并考虑深浅主题变化。不要每次 `OnGUI` 创建纹理或大量样式。GUIStyle 的命名空间与 USS 不同，不能直接套变量代码。

## 对照示例

**不合适：**资源工具顶部放 80px 大标题，接三张“资源数 / 分组数 / 已优化”统计卡；每行有三个彩色按钮；文件名截断且没有完整路径。

**更合适：**顶部一行搜索和主要命令；左边分组、右边固定列宽的资源列表；状态在对应行与底部汇总；多选命令在明确入口中，完整路径可读取。

**不合适：**批量改名只有输入框和“立即执行”，预览被折叠，红色高亮没有原因。

**更合适：**先选范围，始终显示原名和目标名；每项显示冲突原因；按钮写明将处理多少项；结果留在窗口内可复查。
