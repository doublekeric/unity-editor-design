# 验证范围与限制

## 已观察到什么

本 skill 在开发中做过两组独立新上下文的有/无 skill 配对观察：

| 任务 | 观察结果 |
|---|---|
| 构建记录与失败详情，900×620 | 来源匿名评审略偏无 skill 版的层级；有 skill 版错误正文较舒展 |
| 窄纹理 Inspector，380×620 | 基本持平，轻微偏好有 skill 版的混排和间距 |

双方只看自己的实机图，自主修订一轮后，整体偏好没变。**这些样本没有证明稳定审美增益**，也不说明 skill 无用；它是设计过程与检查的辅助，不是保证漂亮的模板。

限制：每任务各一次生成；没有固定随机种子或严格 token 预算；reviewer 不知来源映射但接触过 skill 正文，因此不是严格双盲。测试手工提供了 skill，不是自然语言自动触发测试。

公开仓库仅保留方法和结论，不包含开发环境的完整会话记录、路径、控制台日志或候选产物。

## 可运行复杂示例

[资源审查台](../examples/complex/README.md) 包含24条内存假数据、三栏、混合多选、详情收折、组合筛选、排序、冲突预览和模拟应用。

在 Unity 2022.3.62f2 / Windows / 缩放1下验证过：

- 编译、FontAsset 中英样本文字与真实 Bold 面。
- 14项程序化状态检查：过滤、空态、多选、主题保留选择、人工/冲突、仅安全项模拟、重复执行、处理项退出问题过滤、详情收折。
- 6项字体/布局/行为检查：字形、粗体面、页签宽度及分离、大小排序、只有冲突时执行禁用。
- 1260×800和1040×720的8种截图，经过独立视觉审查与修订。

该示例有技术辅助代码和审查反馈，不是另一次严格有/无 skill 对照；不能据此声称其它会话一定改进。

## 未验证

真实浅色 Editor、停靠、高 DPI、多显示器、macOS/Linux字体表现、完整真实键鼠与无障碍验收；真实资源导入/改名、磁盘冲突、Undo、千级数据性能。示例颜色切换仅作用于自定义窗口。

## 如何继续评测

1. 选未见任务，不给当前示例布局或颜色模板。
2. 相同模型、任务、数据、技术环境和预算；独立新上下文分别有/无 skill。
3. 候选不读彼此实现；作者可获得相同轮数的自身截图修订机会。
4. 统一实际渲染，截图匿名随机排列；字体、层级、比例、组件状态分别给具体证据。
5. 功能验证独立记录，不用它补偿审美差异。允许无 skill 胜或持平，保留负结果。
6. 区分首轮产出、看图修订、作者直接补修，不能混称为 skill 的自然效果。

在实现任务中，只有代码而没有实际渲染，必须明确标为未验证。
